# 文献调研

**红线（最高优先级）**：论文中的每条参考文献都必须真实存在、真实检索所得。
**永远不要**凭模型记忆"编造"一篇看似合理的文献。宁可少引用，不可假引用。

## 1. 检索策略

1. **构造关键词**：中英文各一套；从课题拆出 2-3 个核心概念，组合检索；用同义词扩展（如"推荐系统" ↔ recommendation system / recommender）。
2. **主路径 thesis_lit_search**（禁止凭记忆写文献；也可以用 Undermind / Elicit / Consensus 发现后走 §2 核验入库）：
   - `query` 必填；`year_from` 限年份；`source` 可指定 semantic-scholar / dblp / arxiv / crossref，缺省 auto（Semantic Scholar → DBLP → arXiv → Crossref 失败降级）。
   - 结果写入检索缓存（02-文献/.lit-cache.json）与审计记录（02-文献/检索记录.md）；每条记录带真实 DOI/URL 与缓存 id。
3. **筛选标准**：优先近 5 年；优先顶会/顶刊/高被引；与课题**直接相关**（能支撑你的方法、场景或对比）。
4. **滚雪球**：好文献的参考文献与引证文献里继续挖（同样走检索，不是记忆）。
5. **数量目标**：开题 10-20 篇；最终论文 15-30 篇。

## 2. 发现工具可以借力，但"正确性"只认核验

**分工**：Undermind / Elicit / Consensus / Google Scholar 这类工具负责**发现**（大规模筛、按结论句追问），
Crossref / OpenAlex / DataCite / PubMed 负责**作证**。发现工具的输出是"候选"，不是"证据"。

1. 在发现工具里检索 → 导出 `.bib` / `.ris` / `.csv`（不要手抄）→ 存进论文仓库（如 `02-文献/导出/undermind.bib`）。
2. 调 `thesis_lit_import`（path 指向导出文件）：逐条拿权威库对账，**只有 verified 的进 refs.bib**；其余写进 `08-合规/文献核验报告.md`。
3. 只想看看某条真假：`thesis_lit_verify`（给 title/doi 单条，或给 path 批量），只出结论不改文献库。
4. 结论怎么处理：

| 结论 | 含义 | 你要做的 |
|---|---|---|
| `verified` | 权威库确认，题名/作者/年份对得上 | 可以引用 |
| `mismatch` | 库里有这条，但字段冲突（常见：DOI 张冠李戴） | 打开原文核对，按**权威记录**改，或换一篇 |
| `not-found` | 各库均查无此文 | 视为疑似编造，**禁止入库**，换文献 |
| `unchecked` | 网络/限流导致没核成 | 联网后重跑；没核过就不许写进论文 |

5. 先查 DOI 再查题名：DOI 精确查只要一次请求就能分出「不存在」和「DOI 指到别的论文」，这是最便宜的一刀。
6. 导出很大时用 `limit` 分片（每次 10-15 条），避免被免费库限流。
7. 已知覆盖盲区：中文期刊在 Crossref 覆盖不全，且 DBLP 近年有反爬——这类文献请到 CNKI/万方/IEEE Xplore 打开原文核对，
   把真实 DOI 补进 refs.bib，并在核验报告的备注里写清「已人工核对原文」。
8. **绝对禁止**：把 `not-found` 的条目改改年份/题名再试、或手工拼一条"看起来对"的 BibTeX。那不是排版问题，是学术不端。

## 3. 收录与留痕（审计证据）

- 选定文献后调 `thesis_lit_save`（参数是检索返回的**缓存 id 列表**）→ 写入 02-文献/refs.bib（自动去重、key 冲突自动加后缀）并追加收录审计行。
- **save 只接受缓存 id**：这是零假文献的机制保证——模型无法向文献库塞入"编造"的元数据。
- 每次检索/收录都自动留痕在 02-文献/检索记录.md（日期/库/关键词/命中/收录）。
- **没有检索记录就没有引用资格**——写综述时只允许引用 refs.bib 里的条目。

## 4. 文献笔记模板（02-文献/笔记/<bibkey>.md）

先用 `thesis_lit_note`（参数：缓存 id 或 bib key）生成骨架（元数据 + 原始摘要 + 五节模板），读原文后补全：

```markdown
# <标题>（<作者>，<年份>，<会议/期刊>）

## 这篇解决什么问题
## 方法/技术要点（3-5 条，自己的话）
## 实验与结论（数据集/指标/结果）
## 与我课题的关系（借鉴什么 / 对比什么 / 差异在哪）
## 可用引用句（直接可写进论文的 1-2 句，注明放哪一章）
```

要点：笔记用自己的话写（防"洗稿式抄袭"），"可用引用句"标注归属（如"绪论-研究现状-主题2"）。

## 5. 文献综述写法（主题式，不是流水账）

1. 把文献按**主题/方法/视角**分组（如"基于协同过滤的方法""基于深度学习的方法"）。
2. 每组：概述该类方法思路 → 代表文献（2-4 篇）→ 该类方法的局限。
3. 组与组之间写清演进逻辑（为什么需要新方法）。
4. 最后一段：指出现有工作的不足（针对你的场景），自然引出本课题——这是综述的落点。
5. 每条引用在文中标注序号 [1]，文末按 GB/T 7714 著录（见 thesis-citation 技能）。

## 6. 常见坑

- 综述变"文献堆砌"：每段必须有"该类方法的局限"这一句。
- 引用陈旧：核心论断配近 5 年文献。
- 笔记与论文脱节：写论文时先回笔记目录，按"可用引用句"组织段落。
